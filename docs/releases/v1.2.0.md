# MAES v1.2.0

**Data:** 2026-06-05
**Tipo:** minor — nova capacidade no `/maes-eval` + mudança de comportamento do `maes upgrade`.

## ✨ Recursos

### `/maes-eval` por texto livre (modo ad-hoc) — caminho de primeira classe

Em um projeto já configurado com MAES, você não precisa mais criar cenários para rodar
o avaliador. Basta passar a tarefa em texto:

```text
/maes-eval corrigir responsividade da tela de pipeline dos projetos
```

O agent monta um **cenário único na hora**, derivando os `expected`/`anti_expected` das
regras relevantes do contexto compilado (guards `block`, `anti-hallucination.json` e
assertions pertinentes), e roda o padrão WITH/WITHOUT/judge. A linha de total no relatório
indica a origem: `Cenários: 1 total (ad-hoc — derivado do argumento)`.

Os cenários `.eval.yaml` continuam suportados — agora posicionados como a opção para
avaliação **repetível** (CI, regressão, comparar antes/depois de mudar contexto), nunca
obrigatórios.

Formalizado no `maes-eval.agent.yaml` (agent **v1.1.0**):

- Novo **Passo 0 — Detectar modo de invocação** (texto livre → MODO AD-HOC; `--scenario`/`--agent`/vazio → MODO CENÁRIO).
- Novo **Passo 2b — Construir cenário ad-hoc**.
- `argument_hint` atualizado: `[TAREFA em texto livre] | [--scenario ID] | [--agent AGENT_ID]`.

## 🔧 Mudanças

### `maes upgrade` atualiza os agents do framework

O `maes upgrade` passa a **sobrescrever** os agents `maes-*` (`maes-analyze`, `maes-review`,
`maes-context-add`, `maes-eval`) a partir do template, em vez de fazer merge. Isso garante
que mudanças nos agents — como o modo ad-hoc — cheguem aos projetos existentes no próximo
upgrade. A mudança está em `_copy_agent_templates` (`init_cmd.py`), que só processa os
templates core; agents fora do namespace `maes-` (catálogo `dev-workflow`, agents
customizados) mantêm o comportamento de merge.

> **Tradeoff:** customizações manuais feitas diretamente em um `.agent.yaml` `maes-*` serão
> sobrescritas no upgrade. Agents `maes-*` são de propriedade do framework.

Não há migração dedicada: a mudança no copy logic é durável e vale para todo upgrade futuro.

## 📝 Documentação

  e os cenários como opcional; o modo ad-hoc deixa de ser "best-effort" e passa a "modo suportado".
